# Phase 7 Design System Design

## Goal

Give the React app a coherent design system and a trust surface worthy of the grounded-answer
pipeline behind it. Phase 7's functional plan produced working but visually undesigned components:
a fixed sidebar with no collapse and no sign-out, a status indicator hardcoded to one stage, raw
backend exception text rendered as user-facing copy, and citations that cannot be traced to the
claims they support. This design closes those gaps and establishes reusable component layers so
later phases compose rather than duplicate.

## Scope

In scope: a reusable component system, the app shell (collapsible sidebar, user menu, sign-out,
grouped thread history), the chat surface (markdown answers, auto-growing composer, truthful run
status, stop control), the trust surface (citation chips with previews, an evidence rail with
in-context quote highlighting, focus contract), the full empty and error state taxonomy, dark mode,
and the backend stream events the truthful UI depends on.

Out of scope: inline citation markers in answer text (requires an agent-contract change), a frontend
test framework (repository rule), conversation branching, message pinning, and response feedback
controls.

## Direction

The subject is an internal evidence tool used all day by five senior analysts reading SEC filings.
The page has one job: ask a question, then verify the answer against the filing without leaving the
screen. The palette is fixed by the brief — neutral shadcn tokens, black and white, no accent hue —
so the design invests in the three axes that remain free.

**Density is the position.** The current root sets `font: 18px/145%` with `#root { width: 1126px;
text-align: center }`, Vite template residue sized for a marketing page. The app drops to a 14px
base on an 8px grid. Analysts scan records; they do not read hero copy.

**Type carries two roles.** Geist Variable, already installed, sets prose. The existing `--mono`
system stack (`ui-monospace, Consolas, monospace`) sets filing identity and every figure, with
`tabular-nums` applied throughout. No new font dependency. The sans/mono split is what makes
`AAPL · 10-K · 2024-10-31 · p.28` read as a record rather than a sentence.

**The signature is the evidence rail.** Not a generic side sheet: a persistent right column that
shows the cited quote highlighted in place inside its surrounding chunk, beneath a monospace filing
stamp. Verification is the product, so the one memorable element is the act of seeing a quote sitting
in its real context. Everything around it stays quiet — no gradients, no color-coded confidence, no
motion beyond the streaming caret and the status pulse.

## Component Architecture

Four layers with a strict dependency direction: `chat` and `app` depend on `common`, which depends on
`ui` and `ai-elements`. Nothing depends upward.

### `components/ui/` — shadcn primitives

Generated by the shadcn CLI and never hand-edited. The repository currently has exactly one
(`button`), so every other control is hand-rolled Tailwind in violation of `frontend/AGENTS.md`.
Install: `sidebar`, `dropdown-menu`, `avatar`, `tooltip`, `hover-card`, `scroll-area`, `skeleton`,
`separator`, `sheet`, `input`, `label`, `textarea`, `badge`, `alert`, `card`, `collapsible`.

### `components/ai-elements/` — two vendored components

This repository's shadcn style is `base-nova` built on `@base-ui/react`, while Vercel's AI Elements
registry ships Radix-based shadcn. Running `shadcn add` against that registry would install Radix
primitives alongside Base UI and could overwrite `components/ui/button.tsx`. Both components are
therefore vendored by hand: copy the source, swap primitive imports for the Base UI equivalents,
keep the logic.

- `conversation` — stick-to-bottom scroll anchoring plus a scroll-to-bottom control. Adds one runtime
  dependency, `use-stick-to-bottom`. Justified: preserving the scroll anchor across container
  resizes, streaming content growth, and user-scroll interruption is roughly 150 lines of
  `ResizeObserver` work that is easy to get subtly wrong. If it conflicts with React 19, fall back to
  a hand-rolled hook of about 40 lines.
- `prompt-input` — auto-growing textarea, Enter to send with Shift+Enter for a newline, and a
  status-aware submit/stop button.

### `components/common/` — shared pieces

Each has three or more real callers today, so none is a premature abstraction.

- `FilingMeta` — the monospace filing stamp. Callers: chip tooltip, hover preview, evidence panel
  header.
- `EmptyState` — icon, title, body, action. Callers: no thread selected, empty thread, no search
  results.
- `ErrorNotice` — `variant: 'inline' | 'panel'`. Callers: chat error, history load error, evidence
  panel error, thread list error.

### `components/app/` and `components/chat/`

Shell: `AppSidebar`, `ThreadGroup`, `ThreadItem`, `UserMenu`, `ThemeProvider`.

Chat: `ChatHeader`, `MessageList`, `UserMessage`, `AssistantMessage`, `MessageActions`,
`CitationChip`, `CitationPreview`, `CitationList`, `EvidencePanel`, `EvidencePanelBody`,
`QuoteHighlight`, `RunStatus`, `ChatError`, `ChatEmptyState`, `Composer`,
`InsufficientEvidenceNotice`.

## App Shell

```text
SidebarProvider (cookie-persisted open state, Cmd+B)
├── AppSidebar  collapsible="icon"
│   ├── SidebarHeader   brand + SidebarTrigger
│   ├── SidebarContent  New chat · Search · ThreadGroups
│   │                     Today / Yesterday / Previous 7 days / Older
│   └── SidebarFooter   UserMenu → avatar, email, theme, sign out
└── SidebarInset
    ├── ChatHeader   trigger (mobile) · thread title · evidence toggle
    ├── row → MessageList (max-w-3xl, centered) │ EvidencePanel
    └── Composer
```

The sidebar collapses to an icon rail rather than hiding entirely, so new-chat, search, and the user
avatar stay reachable at all times. The user menu in `SidebarFooter` is what makes sign-out reachable
at all; `pages/ProtectedPage.tsx` exists only to hold that orphaned button and is deleted.

Threads group by `updated_at` into Today, Yesterday, Previous 7 days, and Older. Client-side search
filters titles.

**Thread titles.** Nothing sets `title` today — `create_thread` stores whatever it receives and the
frontend passes `null`, so every thread reads "Untitled chat" forever. Add
`PATCH /chat/threads/{id}` and set the title from the first user message, truncated to roughly 48
characters at a word boundary.

## Chat Surface

User messages are right-aligned filled bubbles capped at 75% width. Assistant messages have no
bubble: full-width prose on the page background with a small monospace eyebrow, so long grounded
answers read as documents. Answer text renders as markdown — headings, lists, and tables, because
filing answers are frequently tabular — with figures in `tabular-nums` and a caret while text
streams.

Message actions (copy) reveal on hover and remain present for keyboard users.

The composer is an auto-growing textarea capped at eight rows. Enter sends, Shift+Enter inserts a
newline. During a run the submit control becomes Stop. A failed send restores the draft.

`RunStatus` renders one line beneath the last message inside `role="status" aria-live="polite"`:
completed stages as muted ticks, the current stage as a pulsing dot and label. It reads real
`data-status` events and never infers progress from a timer.

## Trust Surface

Citations remain a trailing set rather than inline markers, because `assistant/instructions.md`
explicitly forbids citation notation in answer text and changing that contract is out of scope. The
chips are upgraded to carry their weight.

`CitationChip` shows citation index, ticker, filing form, and page in monospace. Hovering opens a
`HoverCard` preview containing `FilingMeta` and the quote clamped to three lines, with an action that
opens the evidence rail. The selected chip takes a filled state so the rail's contents are always
traceable back to the chip that produced them.

The evidence rail is a bordered `<aside>` of `26rem` at `lg` and above, and a bottom `Sheet` below
that breakpoint. Both render the same `EvidencePanelBody`: the `FilingMeta` stamp, then the full
chunk text with the cited quote wrapped in a `<mark>` and scrolled into view, then an external link
to the filing. `QuoteHighlight` splits `chunk_text` on `quoted_text` and falls back to plain text
when no match is found. Dates render through `Intl.DateTimeFormat`, not as raw ISO strings.

**Focus contract:** opening the rail moves focus into the panel; Escape or Close returns focus to the
chip that opened it. The Phase 7 spec requires this and the current implementation does not do it.

A finished assistant message with zero citations renders `InsufficientEvidenceNotice` above its text
and suppresses the sources block entirely. The treatment is muted and bordered rather than
destructive, because a withheld answer is the system working correctly.

## States

Loading uses skeletons shaped like the content they replace, never a bare "Loading…" string.

| Trigger | Treatment |
| --- | --- |
| No thread selected | `EmptyState` — "Ask about a filing" with three clickable example questions from the client brief |
| Thread with no messages | `EmptyState` with the same example prompts |
| `data-error: retrieval_failed` | "Filing search failed. Your question wasn't answered." with Retry |
| `data-error: grounding_failed` | "Answer withheld — its evidence couldn't be verified." Shield icon, muted, not destructive |
| `data-error: processing_failed` | Neutral retry message |
| `ApiError` 401 | "Your session expired." with a sign-in link |
| `ApiError.isNetworkError` | "Can't reach the backend." with Retry; draft preserved |
| `ApiError` 403/404 on a thread | "This chat isn't available." with a link back to the list |
| Evidence panel fetch failure | `ErrorNotice variant="panel"`; the conversation is untouched |

No backend exception text is ever rendered. The current code renders `error.message` in four places,
which the Phase 7 spec explicitly forbids.

## Backend Additions

The truthful status UI cannot exist without stream events the backend does not yet emit —
`chat/streaming.py` currently sends only `start`, `text-*`, `data-citations`, and `finish`, so Phase 7
Task 2 is unimplemented.

- `app/chat/stages.py` — `Stage` and `ErrorCode` literal types.
- `orchestrator.py` — accept an async `on_stage` callback and invoke it immediately before each real
  operation.
- `streaming.py` — emit `data-status` and `data-error` parts.
- `api/chat.py` — begin the response generator before orchestration so `searching` arrives before the
  first token; map post-stream failures to typed `data-error` parts rather than exception text.
- `PATCH /chat/threads/{id}` for titles, with ownership checks matching the existing endpoints.

Backend tests cover stage ordering, typed error emission, absence of leaked exception text, and title
update ownership.

## Cleanup

Delete `src/App.css` (184 lines of Vite template), `src/pages/ProtectedPage.tsx`, and the unused
`hero.png`, `react.svg`, and `vite.svg` assets. Strip template CSS from `src/index.css`: the `#root`
width and centering, the 18px root font, and the `--text`, `--bg`, `--code-bg`, and `--social-bg`
variables that duplicate and fight the shadcn tokens. Wire the existing but dead `.dark` token block
to a real `ThemeProvider` that defaults to the system preference and persists a manual override to
`localStorage`. Reformat the single-line `App.tsx` and `AuthPage.tsx`, and rebuild `AuthPage` on
`Card`, `Input`, `Label`, and `Button`.

## Verification

Frontend verification follows the repository's no-frontend-tests rule: `pnpm tsc --noEmit`,
`pnpm lint`, `pnpm build`, and manual browser checks covering sidebar collapse and mobile sheet,
sign-out, thread grouping and titling, live stage progression, stop, markdown answers, citation hover
and selection, evidence rail on both breakpoints, focus restoration, dark mode, and each mapped empty
and error state.

Backend verification is `uv run pytest -m 'not integration' -q` and `uv run ruff check app tests`.

## Acceptance Criteria

- The sidebar collapses to an icon rail and restores, and works as a sheet on narrow screens.
- A signed-in user can see their identity and sign out without leaving the chat.
- Threads are titled from their first message and grouped by recency.
- Run status reflects real backend stages and never advances on a timer.
- Assistant answers render markdown, including tables.
- Every citation chip previews on hover and opens the evidence rail on click.
- The evidence rail highlights the cited quote inside its surrounding chunk.
- Closing the rail returns focus to the chip that opened it.
- No backend exception text reaches the user in any failure path.
- Dark mode follows the system preference and honors a manual override.
- Type checking, linting, the frontend build, and backend fast tests pass.
